# 分组决策策略设计（v5）

本文说明 `score-calibration policy` 的数据模型、候选生成与组合选择两项分离职责、
精确动态规划的正确性论证与发布语义。仅使用 Python 标准库；本链路不读写修订账本
或监测数据库。数据契约见 [contract.md](contract.md)。

## 1. 数据模型与确定性

- 输入经 `validate_request` 严格校验后，training/evaluation 数组按 `id` 排序、
  `cohort_rules` 按键排序，因此源数组换序不改变任何后续结果。
- `source_sha256` 是对**规范化请求**（排序后、仅含精确整数与字符串）取排序键紧凑
  UTF-8 JSON 的 SHA256，而不是原始文件字节；这是"输入数组换序不得改变策略字节"
  的直接推论。
- 概率复用 v1 的 `isotonic.fit`（同一套加权 PAVA），再用 `bisect_right` 在块下界上
  做左闭阶梯预测；阈值、覆盖量、误接受量与全部比较都是精确 `Fraction`/整数，不
  经过浮点。
- 策略不含时间戳、随机数或环境字段；`policy_sha256` 是对"去除自身 SHA 字段后的
  排序键紧凑 UTF-8 JSON"取 SHA256，外部可独立复算。

## 2. 职责分离

### 2.1 候选生成（`generate_candidates`）

对每组：取该组评估行实际预测概率的**每个不同精确值**作为候选阈值，再附加一个
严格大于 1 的拒绝全部哨兵（序列化为 `">1"`，排序键视为最大）。接受规则左闭：
概率 `>=` 阈值即接受，故哨兵接受零行。每个候选精确计算：

- 正例覆盖量 = 接受行中 label=1 的 weight 之和；
- 误接受量 = 接受行中 label=0 的 weight 之和；
- 排序后的 accepted_ids 与局部合格标记（覆盖量 `>= min_positive_weight`）。

由于 `min_positive_weight` 是正整数（>= 1），哨兵（覆盖量 0）永不局部合格；它仍
被完整生成并标记，供组合选择职责统一消费。PAVA 平台上并列的多行共享同一个概率
值，只产生一个候选阈值。

### 2.2 组合选择（`select_combination`）

在共享 `false_positive_budget` 下为每组**恰选一个局部合格候选**，目标严格按字典序：
`(总覆盖量最大, 总误接受量最小, 按 cohort 字典序排列的阈值向量字典序最小)`。

实现为按组推进的精确动态规划：

- **状态**：已用误接受权重的精确整数值 → `(累计覆盖量, 阈值向量)`。只有已用误
  接受完全相同的部分解才合并；**不同预算状态绝不合并**（已用 3 与已用 4 是两个
  独立状态，不做"支配即丢弃"的跨状态化简）。
- **合并规则**：同一状态内保留覆盖量最大者；覆盖量相同保留阈值向量字典序最小
  者。字典序是前缀序——前 k 个 cohort 的向量一旦更小，追加任何相同后缀都不会
  反转，因此按组推进时逐状态取前缀最小是精确的。
- **剪枝**：仅丢弃 `已用误接受 > budget` 的状态。误接受量单调不减，超预算状态
  永不可行，丢弃是精确的。**不做任何基于覆盖上界的剪枝**，因此在覆盖上界相等
  时不可能误丢字典序更优的解；除超预算外没有任何信息被丢弃。
- **终态选择**：在所有最终状态（不同的已用误接受）上取覆盖量最大、再取误接受
  最小、再取向量最小者。状态合并规则保证每个状态内的代表元就是该状态的最优
  部分解，跨状态比较补全了目标的第二、第三层，整体即全局最优。

为什么不用"各组独立最优再拼接"：各组各自的最大覆盖候选合在一起可能超出共享
预算（见 `tests/test_policy.py` 的联动样例），截断或拒绝都会丢失可行的次优组
合；DP 在联合约束下精确求解，天然避免该陷阱。同理，任一组 label/weight 更正后
整次请求重新求解（无增量缓存），其他组的阈值随共享预算自动重选，保持预算可行
并继续满足全局目标。

## 3. 不可行的两种形态

- **组缺口**：某组所有候选（含接受一切的最低阈值）都达不到
  `min_positive_weight`。缺口 = 下限 − 该组最大可达覆盖量，按组如实报告。
- **预算缺口**：各组均有合格候选，但最便宜的合格组合（各组合格候选的最小误接
  受量之和——各组独立可取，故该下界精确）仍超过 budget。缺口 = 该和 − budget。

两种形态都返回 `status=infeasible` 的完整收据（退出 0），不发布策略、不写输出
文件、不输出部分策略，既有输出保留。

## 4. 发布语义

- 输出已存在且逐字节相同 → 幂等成功（退出 0）；不同 → 保留旧文件报冲突
  （退出 2）；符号链接拒绝。
- 成功发布走临时文件 + 原子 `os.replace`；输入或计算错误退出 2 并保留旧输出。
- 合法但不可行退出 0 且不触碰输出；这与 v3 标注包的"合法但 infeasible 退出 0"
  约定一致。

## 5. 验证

`tests/test_policy.py`：手算边界样例（左闭等值接受、PAVA 平台并列阈值、组下限、
概率 0/1 不裁剪）、独立精确穷举 oracle（400 个随机实例全量比对可行与不可行结
果）、联动样例（各组最大覆盖超出共享预算；单行 weight 更正移除某组原最优候选并
迫使另一组改选阈值；预算可行性、目标顺序、两组策略与输入摘要一起变化）、局部最
优不可行但次优可行的样例、输入换序字节不变、自校验摘要外部复算、幂等/冲突/符号
链接/不可行不发布等 CLI 行为。
